# QuickDrop 使用说明

> 一句话：**电脑上双击运行，手机扫二维码，同一个 WiFi 下双向传文件**。全程局域网直连，不经过任何外部服务器、不上传云端。

---

## 一、前置条件

| 项 | 要求 |
|---|---|
| 电脑 | Windows（已验证）；macOS / Linux 可尝试源码运行但**未验证** |
| Python | 3.10+（开发运行；用 exe 则不需要） |
| 手机 | 与电脑连**同一个 WiFi** |
| 浏览器 | 手机端任意现代浏览器（Chrome / Edge / Safari） |
| 防火墙 | 首次运行需允许「专用网络」访问 |

---

## 二、启动方式

### 方式 A：双击 exe（日常使用）

1. 双击 `dist/QuickDrop.exe`
2. 首次启动约 3~10 秒（单文件 exe 需要解包），之后弹出主窗口
3. **首次运行**若弹出「Windows 安全中心」防火墙提示，务必点**允许访问**（勾选"专用网络"），否则手机连不上
4. exe 是图形程序，**没有黑色命令行窗口**，这是正常的

> 关闭窗口 = 停止服务并退出程序。不做后台常驻、不做开机自启。

### 方式 B：源码启动（开发/调试，能看控制台日志）

```bat
cd quickdrop
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
run.bat
```

或手动执行 `.venv\Scripts\python.exe server.py`。

**启动成功的样子**：

```
=== QuickDrop 启动 ===
mDNS 已发布 http://quickdrop.local:8765/
手机访问地址：http://192.168.x.x:8765/?token=********
本机自检页（含二维码）：http://127.0.0.1:8765/
二维码文件：...\quickdrop\qrcode.png
日志文件：...\quickdrop\logs\quickdrop.log
```

### 方式 C：无头模式（不开窗口，只看日志）

```bat
cd quickdrop
set QUICKDROP_HEADLESS=1
.venv\Scripts\python.exe server.py
```

按 `Ctrl+C` 退出。适合远程或无桌面环境。

> macOS / Linux 用 `export QUICKDROP_HEADLESS=1`。

## 三、怎么让手机连上（最容易踩的坑）

1. 手机连**同一个 WiFi**（不是一个 WiFi 一个流量）
2. 用手机**相机扫窗口里的二维码**，或手动输入 `http://<电脑局域网IP>:8765/?token=<token>`
3. 🚫 **手机上不要输 `127.0.0.1`** —— 那指的是手机自己，必然"无法打开页面"。要用**电脑的局域网 IP**
4. 首次运行请在弹出的防火墙对话框点**允许访问**

> 电脑本机浏览器打开 `http://127.0.0.1:8765/` 会看到**引导页**（大字 + 二维码 + 用法说明），这是给电脑上自检用的，不是手机页。

## 四、三个界面，别混淆

| 界面 | 在哪打开 | 给谁用 |
|---|---|---|
| **电脑主窗口** | 启动后弹出的窗口 | 看二维码、共享文件、打开接收目录 |
| **手机页面** | 手机扫码后 | 上传、下载、发文本 |
| **本机引导页** | 电脑浏览器开 `http://127.0.0.1:8765/` | 电脑上自检、放大看二维码 |

### 电脑主窗口（自上而下五块）

| 区域 | 内容 |
|---|---|
| ① 品牌标题栏 | 「QuickDrop 快传」+ 副标题「同一 WiFi 直传 · 不经过任何外部服务器」；右侧服务状态灯 |
| ② 二维码卡片 | 二维码图片 + 「手机扫这张码」提示 |
| ③ 连接信息卡片 | 「手机访问地址」（可选中复制）、**复制地址**按钮、固定主机名 |
| ④ 共享文件卡片 | **拖拽区** + 按钮：移除所选 / 刷新 / 打开接收目录 |
| ⑤ 状态栏 | 「运行中 ｜ 共享 N 个 ｜ 已接收 M 个文件」 |

### 手机页面

- **上传区**：选择文件 → 上传到电脑（带进度条）
- **共享文件区**：列出电脑共享的文件，点文件名下载
- **文本快传区**：输入文字 → 发送到电脑剪贴板

## 五、操作步骤

### 手机 → 电脑：上传文件

1. 确认手机与电脑连的是**同一个 WiFi**
2. 手机用**相机扫码**，点提示打开链接
3. 点"选择文件"（可多选）→ 点上传
4. 电脑上弹**系统通知**；文件出现在 `received/` 目录
5. 想立刻查看，点主窗口的**打开接收目录**

> 同名文件不会覆盖，会自动改名成 `xxx(1).txt`、`xxx(2).txt`。
> 中文文件名原样保留，「会议纪要.docx」不会被剥成「docx」。

### 电脑 → 手机：共享与下载

1. 把文件或**整个文件夹拖进主窗口的共享列表**（文件夹会递归展开）
2. 不能拖时：把文件放进 `shared/` 目录，并在 `config.json` 里设 `use_shared_dir: true`
3. 手机上点文件名即可下载
4. 不再共享：选中 → **移除所选**，或点**刷新**

### 文本快传

手机页面输入文字发送 → 电脑剪贴板被写入 → `Ctrl+V` 粘贴。

电脑主窗口的 **「文本快传」** 卡片会同时显示收到的内容与时间，便于确认是否送达；
若剪贴板被其他程序占用导致写入失败，手机端会提示，可在窗口里点 **「复制到剪贴板」** 重试。

### 装成 App（PWA，可选）

手机浏览器打开后 → 菜单选**添加到主屏幕** → 之后从桌面图标打开。
注意：**首次仍要扫码一次**（用于种 Cookie），之后免扫。

### 用固定域名访问（mDNS，可选）

路由器支持组播时，手机可直接访问 `http://quickdrop.local:8765/?token=<token>`，电脑 IP 变了也不用改书签。打不开说明该网络屏蔽了 mDNS，用 IP 访问即可（不算故障）。

### 退出

点主窗口右上角 **×** → 服务和程序一起退出，端口释放。

## 六、配置文件 `config.json`

首次运行自动生成在程序目录下，用记事本可改，**改完需重启**。

| 字段 | 默认 | 说明 |
|---|---|---|
| `host` | `0.0.0.0` | 监听地址。改成 `127.0.0.1` 则只允许本机访问 |
| `port` | `8765` | 端口，被占用时可改 |
| `token` | 随机 12 位 | 访问口令。删掉此值会重新生成，手机需重新扫码 |
| `mdns_hostname` | `quickdrop.local` | 固定主机名 |
| `enable_mdns` | `true` | 是否发布 mDNS |
| `received_dir` | `received` | 手机上传文件的落盘目录 |
| `shared_dir` / `use_shared_dir` | `shared` / `false` | 是否把 `shared/` 整个目录当作共享 |
| `max_upload_size_mb` | `4096` | 单次请求大小上限 |
| `notify_on_upload` | `true` | 收到文件是否弹系统通知 |
| `open_folder_on_notify_click` | `true` | 点通知是否打开接收目录 |
| `qr_display_mode` | `tkinter` | 二维码展示方式 |
| `enable_https` / `cert_file` / `key_file` | `false` / `cert.pem` / `key.pem` | ⚠️ **预留占位，当前代码不读取**。见 [security-design.md](security-design.md#31-http-明文传输影响最大) |

## 七、运行时生成的文件

首次运行会在**程序目录下**生成：

| 文件/目录 | 用途 |
|---|---|
| `config.json` | 配置（含访问口令） |
| `logs/quickdrop.log` | 运行日志，每次请求一行 |
| `logs/crash.log` | 仅崩溃时出现，含完整堆栈 |
| `received/` | 手机上传到电脑的文件 |
| `shared/` | 可选共享目录 |
| `qrcode.png` | 本次运行生成的二维码 |

> ⚠️ **不要放在只读目录**（如 `C:\Program Files`），否则这些文件写不出来。
> 建议放在桌面、文档或任意普通文件夹。也可以把整个 `dist` 文件夹拷到 U 盘单独用。

## 八、常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 手机**打不开页面** | 没连同一 WiFi / 输成 `127.0.0.1` / 防火墙没放行 | 用主窗口那个 `http://192.168.x.x:8765/...` 地址；防火墙点允许 |
| 页面**一直转圈/空白** | WiFi 有「AP 隔离」或走了访客网络 | 关掉路由器 AP 隔离，或换到主网络 |
| 能开页面但**报 403** | 口令不匹配 | 重新扫主窗口的二维码 |
| 引导页**看不到二维码** | 服务没起，或端口被旧进程占用 | 看 `logs/quickdrop.log`；`netstat -ano \| findstr :8765` 查端口 |
| **双击 exe 没反应** | 启动异常 | 看 `logs/crash.log` 与 `quickdrop.log` 尾部 |
| 二维码显示**"无二维码文件"** | 缺 Pillow | `pip install -r requirements.txt`，或重新打包 |
| **收到的文件不见了** | 程序放在只读目录 | 移到桌面/文档等可写目录重跑 |
| 传输**很慢/中断** | 信号差、2.4G 频段、路由器限速 | 靠近路由器、改用 5G 频段 |
| 电脑 IP 变了书签失效 | DHCP 重新分配 | 用 `quickdrop.local` 访问，或重扫二维码 |
| 关窗后端口还在听 | 有残留进程 | `netstat -ano \| findstr :8765` 找 PID 后 `taskkill /F /PID <pid>` |
| 杀毒软件报警 | 自编译 exe 常见误报 | 加信任；或改用 `run.bat` 跑源码 |

## 九、日志与排障

日志目录：源码运行 → `quickdrop/logs/`；exe → `dist/logs/`。

`quickdrop.log` 每行形如：

```
10:47:58 INFO  [waitress-0] req=2b7d258f GET /? -> 200 127.0.0.1 (1ms)
10:47:58 WARNING [waitress-2] req=6005680e 拒绝(403) GET /api/files remote=<手机侧IP>
```

`req=` 是这次请求的唯一编号，同时出现在响应的 `X-Request-Id` 头里，可双向定位。

看最后 20 行（在程序目录打开命令行）：

```bat
powershell -NoProfile -Command "Get-Content -Tail 20 'logs\quickdrop.log'"
```

**日志里 token 一律显示为 `token=***`，不会把口令写到磁盘。**

## 十、卸载 / 清理

直接删除程序所在文件夹即可。程序无注册表项、无系统驻留、不写系统目录。

- 只清空收到的文件 → 删 `received/` 内容
- 重置所有设置与口令 → 删 `config.json`
