# 安全设计

本文档说明 QuickDrop 的安全边界、已实现的安全控制、以及**已知的安全局限**。

> 版本对应：QuickDrop 0.1.0（2026-10）
> 相关文档：[SECURITY.md](../SECURITY.md)（漏洞上报方式）· [architecture.md](architecture.md)（架构与数据流）

---

## 一、安全边界

QuickDrop 的设计目标是**局域网内点对点直传**，这决定了它的安全模型：

| 特性 | 说明 |
|---|---|
| 传输范围 | 仅同一局域网（同一 WiFi / 同一交换机） |
| 是否经过外部服务器 | **否**。不联网上报、不使用云存储、无遥测 |
| 监听地址 | 默认 `0.0.0.0`，即对局域网内所有设备开放 |
| 服务生命周期 | 手动启动，**关窗口即退出**，不常驻、不自启 |
| 数据落盘 | 手机上传的文件落在你本机 `received/` 目录 |

**这意味着**：同一局域网内的任何设备理论上都能访问这个端口。因此访问口令（token）是唯一的防线，请务必不要在公共 WiFi 下长时间运行。

## 二、已实现的安全控制

### 2.1 访问控制

**12 位随机访问口令**，首次启动时用 `secrets.choice()` 生成（密码学安全随机源，非 `random` 模块），持久化在 `config.json`。校验通过三个通道，兼容不同入口：

| 通道 | 形式 | 适用场景 |
|---|---|---|
| URL 参数 | `http://<ip>:8765/?token=<token>` | 扫码直连 |
| 请求头 | `X-Token: <token>` | 程序化调用 |
| Cookie | `qd_token`，`HttpOnly` + `SameSite=Lax` + 1 年 | 扫码后自动携带，免重复输入 |

免鉴权的白名单被压到最小：仅 `/api/health`（健康检查，不返回任何数据）、`/api/clipboard` 的 GET 取值（受 Origin 校验保护）、以及本机引导页 `http://127.0.0.1:8765/`。

**换口令**：删除 `config.json` 中的 `token` 值后重启，会重新生成。手机端已种的 Cookie 同时失效，需要重新扫码。

### 2.2 防止 DNS 重绑定（Host 白名单）

服务绑定 `0.0.0.0` 时会接受任意 `Host` 头。攻击者若控制一个指向你内网 IP 的域名，浏览器访问后会认为那是自己的同源，从而可以用 JS 读你的 API。

**缓解**：`_host_allowed()` 只放行 IP 字面量、`localhost`、以及配置的 mDNS 主机名，其余返回 `421 Misdirected Request`。

判定依据是「是否 IP 字面量」而非「是否等于当前 IP」，因此多网卡、IP 变动都不影响正常使用。

### 2.3 防止 CSRF（Origin 同源校验）

写操作（上传、删除、改剪贴板）会校验 `Origin`（退化时用 `Referer`）：跨站来源或 `Origin: null` 返回 `403`。无来源头的脚本请求与真机请求放行，交由 token 守卫兜底。

配合 Cookie 的 `SameSite=Lax` 形成双层防护。

### 2.4 文件处理安全

| 风险 | 处理方式 |
|---|---|
| 路径穿越 | 显式拒绝 `..`、`/`、`\`，并做 `abspath` 前缀包含校验 → `400` |
| 中文文件名丢失 | 自研 `safe_filename()` 替代 `werkzeug.secure_filename`（后者会把「会议纪要.docx」剥成「docx」） |
| Windows 保留设备名 | 拦截 `CON`/`PRN`/`AUX`/`NUL`/`COM1-9`/`LPT1-9` |
| 控制字符 | 剔除 `\x00-\x1f` |
| 同名覆盖 | `unique_path()` 用 `os.open(O_CREAT\|O_EXCL)` **原子独占创建**，并发同名上传不会互相覆盖 |
| 文件 ID 可预测 | 由无盐 MD5 改为**带进程随机盐的 HMAC-SHA256**（保持 8 位长度） |

`safe_filename()` 在保留 Unicode 的同时只剔除真正危险的字符，上限 200 字符，结果为空时回落 `unnamed`。

### 2.5 HTTP 响应头

统一追加：

```
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: no-referrer
Cache-Control: no-store     # 仅 /api/* 前缀
```

### 2.6 资源耗尽防护

| 项 | 限制 | 超限响应 |
|---|---|---|
| 剪贴板文本 | 1 MB | `413` |
| 单次上传 | `max_upload_size_mb`（默认 4096 MB） | `413` |
| 磁盘空间 | 上传前预检接收目录剩余空间（预留 10% 余量） | `507`，且不落半截文件 |

### 2.7 日志脱敏

所有请求日志中的 `?token=` 一律替换为 `token=***`，明文口令**不会落盘**。日志每行带 `req=<8位编号>`，与响应头 `X-Request-Id` 同值，可双向定位。

### 2.8 供应链

- `requirements.txt` 全部依赖带**兼容上界**（`>=x,<y`），避免 `pip install -U` 静默引入破坏性升级
- `requirements.lock` 提供 22 条精确版本的可复现基线
- 依赖经 `pip-audit` 扫描：**22/22 依赖、0 条已知漏洞**（扫描于 2026-10-08，漏洞库是时点数据，建议发版前重跑）

### 2.9 启动期安全自检

启动时把生效中的安全边界逐条写入日志（`[安全自检]` 前缀），包括：是否对全网卡开放、Host 白名单范围、接收目录与剩余空间、token 存放位置。**若检测到当前处于 Git 工作树，会告警不要提交 `config.json`**。

## 三、已知局限（请认真阅读）

这些**不是待修的漏洞，而是当前设计范围内的取舍**：

### 3.1 HTTP 明文传输（影响最大）

**QuickDrop 只用 HTTP，没有 HTTPS。** `config.json` 里虽然有 `enable_https` / `cert_file` / `key_file` 三个字段，但**当前代码并不读取它们**——那是预留占位，不要依赖。

后果：同一局域网内的其他设备理论上可以**嗅探**你的传输内容与访问口令。家用网络风险较低，**公共 WiFi（咖啡厅、酒店、机场）风险显著升高**。

对策：只在可信网络下使用；需要跨网络传输时改用其他方案。

### 3.2 token 明文存储

token 以明文存在 `config.json`（程序目录下）。若该目录被他人可读，或你把整个目录上传到了别处，口令即泄露。

项目为此做了两件事：`.gitignore` 忽略 `config.json`；启动时检测到 Git 工作树就告警。**但请你自己也注意不要把 `config.json` 连同目录一起分享出去。**

### 3.3 局域网内人人可访问

只要服务在跑，**同一局域网内所有设备**都能访问该端口。token 是唯一屏障。因此：

- 不要在公共或半公开网络长时间开着
- 传输敏感文件后，关掉窗口即失效
- 换口令：删 `config.json` 里的 `token` 值后重启

### 3.4 共享文件的访问控制粒度

拿到 token 的人可以**下载全部共享文件**、**上传任意文件**。没有细粒度的目录级权限，也没有传输审批——这是设计上的简单性取舍。

### 3.5 其他

- 端口默认 `8765`，绑定 `0.0.0.0`。若只想本机使用，把 `config.json` 的 `host` 改成 `127.0.0.1`
- mDNS（`quickdrop.local`）会向局域网广播主机名，部分网络可能屏蔽；`enable_mdns: false` 可关闭
- 不做开机自启、不做系统托盘常驻，**关闭窗口即完全退出**——这是特性，不是缺陷

## 四、验证方式

开发期使用了一套内部探针脚本（未随源码开源）覆盖上述控制点，基线如下：

| 探针 | 覆盖内容 | 结果 |
|---|---|---|
| 安全探针 | `safe_filename` 9 例、Host 白名单、Origin 校验、并发落盘、HMAC file_id、安全响应头、剪贴板限长、依赖上界、磁盘预检、启动自检 | 47/47 通过 |
| 功能回归 m1/m3/m4/m4b | 上传下载、共享管理、日志与二维码、PWA 资源 | 26/26 · 28/28 · 11/11 · 18/18 通过 |
| GUI 视觉 | 主窗口元素与拖拽区 | 19/19 通过 |
| 打包 exe 端到端 | 真实 exe 进程的鉴权、响应头、中文名落盘、关闭后端口释放 | 25/25 通过 |

**如果你想自己复验**，最简单的方式：

```bash
# 1. 启动服务（无头模式）
cd quickdrop
set QUICKDROP_HEADLESS=1
.venv\Scripts\python.exe server.py
```

```bash
# 2. Host 头应被拒（返回 421，不是 200）
curl --noproxy "*" -H "Host: evil.com" -i http://127.0.0.1:8765/api/health

# 3. 安全响应头应齐备
curl --noproxy "*" -I http://127.0.0.1:8765/api/health
```

预期：第 2 条返回 `421`；第 3 条响应头包含 `X-Content-Type-Options`、`X-Frame-Options`、`Cache-Control`。

> ⚠️ 本机 curl 可能走系统代理，排查连通性时务必加 `--noproxy "*"`，否则会把"网络不通"误判成"服务返回 502"。
